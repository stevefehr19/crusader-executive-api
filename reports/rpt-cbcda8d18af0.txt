WHY THIS REPORT IS PUBLIC. The mission was to make the executive feeds readable
from an ordinary ChatGPT retrieval, and an officer told to check for agent work
could until today find only one operational report, filed two days ago. A
publication surface that carries no current work answers "there is nothing" to a
question about whether anything happened. This report is the current work, so it
is released through the normal classification gate rather than described from
behind it.

THE FINDING

NO SERVER-SIDE CAUSE WAS FOUND FOR THE REPORTED FETCH FAILURE. Every mechanism
was measured rather than reasoned about: robots.txt allows all agents with no
Disallow and no X-Robots-Tag; the host answers 200 to ChatGPT-User, OAI-SearchBot
and GPTBot byte-identical to a plain reader; content-type is application/json with
nosniff; the JSON parses; HTTP/1.1 and HTTP/2 both succeed; IPv4 and IPv6 both
succeed with identical byte counts; gzip and brotli both decode; there are zero
redirects on any endpoint; conditional requests revalidate correctly; write
methods are refused; and the project carries no password gate, no SSO gate and no
bot protection. An independent AI retrieval service on its own network, with no
local access, fetched and quoted back every feed.

SO THE RESIDUAL HYPOTHESIS IS THE RETRIEVAL SURFACE ITSELF, WHICH THIS SIDE
CANNOT MEASURE. It is stated as a hypothesis and not dressed as a finding.

WHAT WAS BUILT IN RESPONSE

1. A MINIMAL REACHABILITY PROBE, /api/ping.json. Three keys, no clock reading, no
   hash, no self-referential url, byte-identical on every build. It exists to
   separate "the fetcher cannot reach this deployment" from "the fetcher reached
   it and could not process the executive payload". A probe carrying a timestamp
   would fail for the second reason while claiming to test the first, so it is
   written outside the endpoint registry where the builder cannot decorate it.

2. A SECOND PUBLICATION ON AN UNRELATED DOMAIN. The executive feeds are now
   published to two independent hosts. One host's relationship with one retrieval
   surface is no longer a single point of failure for whether the officers can
   read anything at all.

3. THE REPORT BODIES THEMSELVES ARE NOW SERVED ON BOTH HOSTS. The second host
   was previously serving a reports feed that read count 0 with an empty array,
   and served no report documents at all. An officer checking it for agent work
   was told, correctly and uselessly, that there was none. That feed now carries
   every published report and every report body is retrievable.

4. A SITEMAP THAT NAMES THE REPORTS. Discovery previously listed seven addresses
   and named no report. A search-backed retrieval could therefore not find the
   work even where a direct fetch would have returned it. All retrievable
   documents, including every report page, are now listed.
